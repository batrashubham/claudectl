# claudectl

CLI tool that backs up, indexes and resumes coding-agent sessions (Claude Code,
Codex, Gemini CLI, opencode, Qwen Code) across machines, written in Go.

## Build & Run

```bash
go build -o claudectl .     # build
go install .                # install to ~/go/bin/
go build ./...              # check all packages compile
./claudectl list            # quick smoke test (no TTY needed)
./claudectl sync            # test sync (needs ~/.claudectl/config.toml)
```

go test ./...               # unit + integration tests (git required)
go vet ./...

CI pins Go 1.25: when adding deps, check `go.mod` still says `go 1.25.0`
(`GOTOOLCHAIN=go1.25.0 go get ...`).

## Architecture

```
cmd/              # Cobra CLI commands (one per file; workspace.go, machine.go, ...)
internal/
  app/            # Env: resolved config + machine + harnesses; shared by cmd and tui
  harness/        # One adapter per agent (claude, codex, gemini, opencode, qwen)
  machine/        # Machine identity, per-machine manifests, cross-machine path mapping
  config/         # TOML config, workspaces, path_map, per-harness overrides
  index/          # Merges sessions from live dirs + every machine's backup subtree
  session/        # Restore (copy or import) + exec the agent
  sync/           # Copy engine, legacy migration, flock, git commit/rebase/push
  template/       # Save/spawn/list/delete Claude Code session templates
  tui/            # Bubble Tea two-pane TUI (sidebar + session list)
```

### Adding an agent

Implement `harness.Harness` in `internal/harness/<name>.go` and `register` it
in `init()`. `Scan(root)` must work on both the live home and a backup copy:
the backup mirrors the agent's own layout under `machines/<m>/<agent>/`.
Optional interfaces: `Exporter` (data that can't be file-copied, e.g. a DB),
`Importer` (restore through the agent's CLI), `RestorePreparer`,
`BinarySetter`. Add real fixtures under `internal/harness/testdata/<name>/`,
generated by the real CLI (a mock model server works) with paths scrubbed.

## Key Design Decisions

- **Append-only sync**: never delete from backup. Copy if dest missing or source larger
  (or newer, for `SyncRoot.Mutable` documents). Copies are temp-file + rename.
- **Per-machine subtrees**: each machine only writes `machines/<name>/`, so pushes from
  many machines rebase without conflicts. Machine name is persisted in
  `~/.claudectl/machine` because hostnames drift. Manifests hold no timestamps so
  unchanged machines don't commit.
- **Legacy layout migration**: backups with `projects/` + `history.jsonl` at the root are
  merged into `machines/<this>/claude/` on sync (history lines unioned, larger file wins),
  but only if never pushed. Once on a remote they may be any machine's, so they stay put
  and are indexed as machine `legacy` (a reserved name).
- **Backups are untrusted input**: they arrive from other machines via the remote. IDs go
  through `harness.SafeID` (no separators, `..`, or leading `-`), and restore confines
  every source/destination path to its root.
- **Restore source**: live copy if any, else the largest backup copy; the session's
  machine/project/key all come from that same copy.
- **History rewrites are local-only**: `gc --squash/--keep-days` refuse when a remote is set
  (a new root commit can't rebase onto the remote's history).
- **Hooks/cron are per workspace** and always pass `--workspace`, so `default_workspace`
  changes never retarget them.
- **Workspaces inherit nothing** from the top level (remote, push, agent homes), so a
  work profile can never push to a personal remote by accident.
- **Never back up credentials**: sync roots are allow-lists per agent.
- **Session ID rewriting**: templates use `strings.ReplaceAll(line, oldUUID, newUUID)` streaming line-by-line. Safe because UUID is unique 36-char string.
- **No background restores**: nothing is written into an agent's own dirs except when the
  user resumes a session. `sync` fetches + rebases the *backup repo* before pushing (needed
  for multi-machine), never the agents' dirs.
- **Lock**: `flock` on `<backup_dir>.lock`, held across copy + commit + rebase/push (and by
  restore, gc, machine rename); the kernel releases it if a sync dies. `sync --wait` queues
  behind a running sync (used by the hook).
- **Git**: `GIT_TERMINAL_PROMPT=0` (hooks/cron can't answer prompts); fallback identity only
  when the user has none; branch is whatever HEAD is (new repos pin `main`).
- **Git signing disabled**: all commits use `--no-gpg-sign` (1Password agent conflicts).
- **Ghost sessions** (FileSize==0): exist in history.jsonl only, file was deleted before backup. Hidden from default view, shown in Ghost filter tab.

## TUI Conventions

- Two-pane: left sidebar (projects + templates), right pane (sessions or template detail)
- Focus: Tab switches panes, j/k navigates within focused pane
- Colors: purple gradient palette, cyan cursor, green active dots
- Background fills for selection (not border boxes — they render poorly)
- lipgloss `Width()` for layout, `JoinHorizontal` for panes

## Session-format notes

### Claude Code (verified against 2.1.220)

- `--trim` is a *remove-list*: unknown entry types are always kept, so new
  Claude Code entry types are safe by default. Re-audit the list when Claude
  Code adds types; see `internal/template/save.go` for what is deliberately kept.
- Background sessions (`claude --bg`) store transcripts in the normal
  `~/.claude/projects/` tree, so the filesystem walk already covers them.
- **Fork lineage is not recoverable.** `--fork-session` rewrites every UUID and
  writes no parent reference, so a fork is indistinguishable from a fresh
  session. Content-prefix matching was evaluated as a proxy and rejected: on
  real data it produced only false positives (shared `<local-command-caveat>`
  boilerplate and repeated opening prompts).
- `SessionEnd` hooks share a 1.5s budget and do not block exit — anything slow
  must set `async: true` or it gets killed mid-operation.
- Project dirs encode the cwd with every non-alphanumeric character as `-`
  (`harness.EncodeClaudeProject`); decoding is lossy, so the transcript's `cwd` wins.

### Codex (verified against 0.160)

- `sessions/YYYY/MM/DD/rollout-<ts>-<uuid>.jsonl`; first line `session_meta`. New rollouts
  record prompts only as `response_item` user messages (skip `<environment_context>` and
  `developer` role); older ones also write `event_msg/user_message`, so prefer those.
- `codex resume <id>` works from any cwd and rebuilds `state_*.sqlite` from the rollout.
  Archived rollouts must be moved back under `sessions/` or resume refuses them.

### Gemini CLI (verified against 0.62)

- `tmp/<slug>/chats/session-*.jsonl` is an event log: replay `$set`, `$rewindTo`, and
  repeated message ids. `<slug>` is the project basename (`projects.json` registry,
  `.project_root` marker); before 0.36 it was sha256(path).
- `gemini --resume` only searches the current project's slug dir. Never restore a
  `.project_root` naming another path — it makes Gemini pick a different slug.
- Resuming writes a stub file with the same sessionId; Scan keeps the fuller one.

### opencode (verified against 1.18.34)

- SQLite (`opencode.db`, WAL) since 1.2.0. Backup = per-session `opencode export` snapshots
  (≈1.7s each, so bounded per sync); restore = `opencode import` (keeps ids). Resume must run
  from the session's directory or it hangs.

### Qwen Code (from 0.24 source, not run)

- `projects/<sanitized-cwd>/chats/<id>.jsonl`, archive in `chats/archive/`.
